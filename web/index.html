findher

Builds you a plan for meeting someone, and refuses to write one sentence about you that you did not say first. The first guard refuses any seed that names a person — try it:

scripts/guards.py — check_seed() runs here, in your browser
REFUSED

findher produces two rooms, a calendar, copy you can defend out loud, and a criterion that is a row in a log file. The rest is you on a Wednesday, walking in.

Above is a trimmed version of the real rules. The shipped version is checked against twelve refusing phrasings and seven honest ones, and the honest ones must all pass — a gate that flags honest input teaches you to skim the output.

An agent skill. Markdown and stdlib Python, no dependencies. MIT.

Why the guard is the product

Ask an assistant to help you meet people and it writes you something confident. With no source material it does not go quiet. It produces plausible sentences.

The next pass does not correct an invented detail. It elaborates it, until the invention is better supported than anything you actually said.

A guard against one symptom does not catch the cause. A check that stops an invented name reaching a live app still passes while the premise behind it stays false.

So: nothing a model wrote about you counts as evidence. Every claim cites a line you wrote yourself. And a claim with no line stays blank, with the question still next to it — because a blank you cannot fill is a wrong question, not a hard question.

Five guards, all of them code

Prose refusals get argued past. Each of these fails the build.

The seed is a type, not a person
Everything downstream — venue lookup, organiser calendars, recurrence, travel time — is a location-intelligence pipeline. Pointed at a category it is planning. Pointed at one person it is stalking, and the only difference is text you would otherwise accept as freeform.
Adult age floor
Required, machine-readable, 18 or over, and it must agree in two files. The seed is freeform and nothing else constrains it.
No protected characteristic as a search axis
A venue whose reason needs a demographic word is refused, and moving the word to another column or padding it with a real clause does not help. The justification language is the tell, because that is the language that leaks into how you talk about the room once you are in it.
No send path
An AST scan over every script, for network imports and send calls. The skill drafts. You send, type, and walk in.
Fail closed
A missing config, an emptied denylist, a renamed column, a routing document pointing at nothing. A preflight that ships with empty lists passes vacuously while printing a green line — that is the defect it exists to catch, sold as a feature.

Every one has been watched failing on injected input:

$ python3 scripts/selftest.py

B1   12 phrasings that name an individual are all refused    pass
B2   7 honest seeds are not refused                          pass
B4   a venue justified by who is there, in 4 shapes          pass

C3   the criterion exits 1 on day one, not 2                 pass
...
21 of 21 cases behaved.

A guard you have never seen fail is a guard you are asserting, not testing.

The run

  1. Bootstrap: clone or scaffoldignore rules staged before anything with content
  2. Seed and decodefour bins: identity, logistical, inoperable, refused
  3. Place and timeasked and restated, never read off the system clock
  4. Research the roomsthe organiser's own page, every row marked
  5. Pick two roomsone for density, one for survivability
  6. Likeness, then presentationevery claim carries a source, or stays blank
  7. Messages and the linterthirteen rules, and nothing that can send
  8. The rigcalendar with a real VTIMEZONE, metadata stripped from photos
  9. The criterion and the ledgerthen stop, and say the rest is yours

The metric that predicts the outcome is showing up to the same thing a fourth time, so being visible in eight places is being invisible in eight places. Rooms entered is about 35% of it and initiating is another 25% — both of those are you on a Wednesday, walking in. The criterion is a row in a log file, and not a document, for exactly that reason.

Install

Clone it and scaffold a plan repo beside it. The ignore rules are staged before any file with content in it exists, and it refuses a destination that already holds something.

git clone https://github.com/jgoetzmann/findher.git
sh findher/scripts/bootstrap.sh ~/plans/thisyear

Or install it as a skill and let the nine steps run as a conversation:

npx skills add jgoetzmann/findher --global

Or as a Claude Code plugin:

/plugin marketplace add jgoetzmann/findher
/plugin install findher@findher

Then say what you want. It triggers on "help me meet people", "put myself out there", "find a scene", and "where should I actually go". It refuses one thing outright: a specific person. That refusal is the whole product.
